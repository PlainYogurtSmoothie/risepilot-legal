RisePilot Privacy Policy

Last updated: September 25, 2026

RisePilot is an alarm and optional planner application published on Google Play by Plain Yogurt Smoothie. Its core alarm features work without an account and without Health Connect.

This policy covers the RisePilot builds distributed through Google Play: the Closed Beta build for invited testers and the Internal Test build for internal testers. Where the builds differ, this policy says so.

Data Stored on the Device

RisePilot stores alarm settings, alarms, presets, planner entries, interface preferences, the latest optional health summary, and small app settings such as update-reminder preferences locally on the user's device, in app-private storage that other apps cannot read. If the user picks a custom alarm sound, RisePilot stores a reference to the chosen file and its name; it does not copy or upload the audio. The Internal Test build also stores the verified purchase status described under "Purchases in the Internal Test Build".

Alarms, alarm settings (including appearance settings and the chosen alarm sound reference), presets, transient alarm state needed after a restart, and a random identifier that RisePilot creates on the device to track local changes use Android's app-private, device-encrypted storage so alarms can be restored before the first unlock. RisePilot does not send this identifier or its local change records anywhere. Planner entries and optional Health Connect summaries are not moved into this Direct Boot storage.

Android Auto Backup is disabled for this app. On some devices running Android 12 or later, Android's device-to-device transfer may still copy the alarm data kept in Direct Boot storage when the user sets up a new phone.

Health Connect

Health Connect integration is optional and disabled by default. If the user enables it and grants permission, RisePilot reads only:

  • today's step total; and
  • total sleep duration recorded during the last 36 hours.

RisePilot reads this data only while the app is open, when the health card is shown or the user taps Refresh, and stores only the latest displayed summary locally. Health data is not used to schedule, trigger, snooze, or dismiss alarms. RisePilot does not write health data, request background health-data access, sell health data, use it for advertising, or send it to RisePilot or any third party. The latest summary is included in the data export file if the user chooses to export, and the user decides where that file is saved.

Users can revoke Health Connect access at any time in Android's Health Connect settings. Revoking access does not affect core alarm operation. Turning the feature off or revoking access stops new reads but does not erase the last saved summary; Delete all user data erases it.

Device Permissions

RisePilot may request or use permissions needed for exact alarms, notifications, vibration, full-screen alarm presentation, screen wake behavior, alarm volume and sound playback, restoring alarms after a restart, physical step detection, and network access used by the Google Play and RevenueCat libraries described below. The Internal Test build also uses the Google Play billing permission.

Physical activity access is requested only for the walking mission, or when the user runs the walking sensor test included in the Internal Test and Closed Beta builds. Step counts from the device's sensor are used only while that mission or test runs and are not saved or sent anywhere. When motion access or a compatible sensor is unavailable, RisePilot displays a clearly labeled manual fallback so the user is not locked into a ringing alarm.

Data Export, Import, and Deletion

Users can save a JSON copy of their local alarm settings, alarms, presets, planner entries, interface preferences, and latest optional health summary from the Data and Privacy screen. The user chooses the destination through Android's system file picker. RisePilot does not upload the export. The file may contain personal information, and after it is saved it is handled by the app or storage location the user chose. Ringtone audio files are not included. Users can also import an export file they choose; RisePilot reads it on the device, and importing replaces the current local data.

Users can also delete this local user data in the app. RisePilot cancels its scheduled alarms before deletion. This does not delete Google Play purchase records, source records stored by Health Connect, permissions managed by Android, or export files the user saved elsewhere; purchase records, Health Connect records, and permissions remain available through the corresponding Google Play or Android settings. In the Internal Test build, it also does not delete the RevenueCat data described below.

Data Retention

RisePilot keeps its local data on the device until the user deletes it in the app, replaces it by importing a data file, or uninstalls RisePilot. Android removes the app's local data when the app is uninstalled. The health summary is replaced each time it refreshes and is erased by Delete all user data. Google Play and Health Connect keep their own records under their own settings and policies; Google states that the data used for Google Play's in-app update check is deleted after a fixed retention period. In the Internal Test build, deleting data in RisePilot does not remove RevenueCat's record or the Block Store copy. In Internal Test version 0.9.10 (22), it also does not remove the saved purchase status, which stays until the app is uninstalled. Internal testers can ask for their RevenueCat record to be deleted by email.

Purchases in the Internal Test Build

The Internal Test build includes in-app purchase testing. Google Play processes these purchases; RisePilot does not receive card or other payment details. To check purchase status, this build uses RevenueCat, a subscription service. While the app runs, including when it starts (also in the background, for example to ring an alarm or after the phone restarts), when it returns to the foreground, and when the tester opens the purchase screen, buys, or restores a purchase, the RevenueCat library can send RevenueCat:

  • a random app user ID created by the library;
  • Google Play purchase details, such as the purchase token, product IDs, price, and currency; and
  • device and app details, such as device model and brand, Android version, language settings, store country, the app's package name and version, and library versions.

Google Play also sends RevenueCat updates about these purchases, such as renewals, cancellations, and refunds. RevenueCat uses this information to confirm purchases and to give us purchase statistics. This build also turns on RevenueCat's SDK diagnostics, which send technical information about the library's operation to RevenueCat, such as response times, error codes, product IDs, and Google Play app versions. Google Play's billing library in this build may also send purchase-flow logs to Google.

Once the tester has made a purchase, the RevenueCat library can save its random app user ID in Google Block Store on the device. If Google backup is on, Block Store can back this ID up to the tester's Google account and keep it after the app is uninstalled. When purchases are restored, the library can use this ID to link a new install to the earlier purchases.

RisePilot also saves the verified purchase status on the device: whether Plus access is active, when it was checked, when it ends, whether it is lifetime, and whether it was a test purchase. Uninstalling the app removes this status and RevenueCat's local files. Current versions also erase the status when the user deletes all user data. Internal Test version 0.9.10 (22) does not. Deleting data in RisePilot does not remove RevenueCat's record or the Block Store copy. Internal testers can ask for their RevenueCat record to be deleted by email (see Contact).

The Closed Beta build does not turn on purchases or RevenueCat and does not send this information.

Google Play Updates

RisePilot uses Google Play's in-app update library to check whether a newer version is available. For this check Google Play uses device information, the app version, and the installed app modules and asset packs; Google states that this data is encrypted and not transferred to third parties. RisePilot stores only its own update-reminder settings on the device.

Security

Apart from the Google Play and RevenueCat libraries described in this policy, RisePilot does not send user data over the network. RisePilot keeps its data in app-private storage that other apps cannot read. On devices that use Android's file-based encryption, the alarm data needed before the first unlock is kept in device-encrypted storage, which Android makes available before the user unlocks the phone. Other data is kept in credential-encrypted storage, which is available only after the phone is unlocked. The data export file is plain JSON and is not encrypted, so users should keep it somewhere they trust. Google states that in-app update data is encrypted, and RevenueCat states that it encrypts data in transit.

Accounts, Analytics, and Advertising

RisePilot has no user accounts. It does not show ads and does not include advertising or crash-reporting SDKs. Other than RevenueCat in the Internal Test build, described above, it does not include analytics SDKs. RisePilot does not use the Android advertising ID and does not track users across other apps or websites. RisePilot is intended for adults and is not designed for children.

Medical Disclaimer

RisePilot is not a medical device and does not provide medical advice, diagnosis, or treatment.

Contact

RisePilot 개인정보처리방침

최종 업데이트: 2026년 9월 25일

RisePilot은 Plain Yogurt Smoothie가 Google Play에 게시하는 알람 및 선택형 플래너 앱입니다. 핵심 알람 기능은 계정이나 Health Connect 없이도 동작합니다.

이 방침은 Google Play로 배포되는 RisePilot 빌드, 즉 초대된 테스터를 위한 비공개 베타(Closed Beta) 빌드와 내부 테스터를 위한 내부 테스트(Internal Test) 빌드에 적용됩니다. 빌드에 따라 다른 부분은 따로 밝힙니다.

기기에 저장되는 데이터

RisePilot은 알람 설정, 알람, 프리셋, 플래너 항목, 화면 설정, 가장 최근의 선택형 건강 요약, 그리고 업데이트 알림 설정 같은 작은 앱 설정을 사용자 기기 안의 앱 전용 저장소에 저장합니다. 다른 앱은 이 저장소를 읽을 수 없습니다. 사용자가 알람 소리를 직접 고르면 RisePilot은 선택한 파일에 대한 참조와 그 이름만 저장하며, 오디오를 복사하거나 업로드하지 않습니다. 내부 테스트 빌드는 「내부 테스트 빌드의 구매」에 설명한 확인된 구매 상태도 저장합니다.

알람, 알람 설정(화면 테마 설정과 선택한 알람 소리의 참조 포함), 프리셋, 재시작 후 필요한 일시적 알람 상태, 그리고 RisePilot이 로컬 변경을 추적하려고 기기에서 만드는 무작위 식별자는 Android의 앱 전용 기기 암호화(device-encrypted) 저장소에 저장됩니다. 그래서 기기를 처음 잠금 해제하기 전에도 알람을 복원할 수 있습니다. RisePilot은 이 식별자나 로컬 변경 기록을 어디에도 보내지 않습니다. 플래너 항목과 선택형 Health Connect 요약은 이 Direct Boot 저장소로 옮겨지지 않습니다.

이 앱은 Android 자동 백업을 사용하지 않습니다. 다만 Android 12 이상을 실행하는 일부 기기에서는 사용자가 새 휴대폰을 설정할 때 Android의 기기 간 전송 기능이 Direct Boot 저장소의 알람 데이터를 복사할 수 있습니다.

Health Connect

Health Connect 연동은 선택 사항이며 기본적으로 꺼져 있습니다. 사용자가 이를 켜고 권한을 허용하면 RisePilot은 다음만 읽습니다.

  • 오늘의 총 걸음 수
  • 최근 36시간 동안 기록된 총 수면 시간

RisePilot은 앱이 열려 있을 때, 즉 건강 카드가 표시되거나 사용자가 새로고침을 누를 때에만 이 데이터를 읽으며, 가장 최근에 표시된 요약만 기기에 저장합니다. 건강 데이터는 알람을 예약하거나, 울리거나, 다시 울리게 하거나, 해제하는 데 사용되지 않습니다. RisePilot은 건강 데이터를 쓰지 않고, 백그라운드 건강 데이터 접근을 요청하지 않으며, 건강 데이터를 판매하거나 광고에 사용하거나 RisePilot 또는 제3자에게 보내지 않습니다. 사용자가 데이터를 내보내기로 선택하면 최신 요약이 내보내기 파일에 포함되며, 그 파일을 어디에 저장할지는 사용자가 정합니다.

사용자는 언제든 Android의 Health Connect 설정에서 접근 권한을 철회할 수 있으며, 철회해도 핵심 알람 기능에는 영향이 없습니다. 기능을 끄거나 권한을 철회하면 더 읽지는 않지만 마지막으로 저장된 요약은 지워지지 않으며, 「모든 사용자 데이터 삭제」를 실행하면 지워집니다.

기기 권한

RisePilot은 정확한 알람, 알림, 진동, 전체 화면 알람 표시, 화면 켜기, 알람 음량 및 소리 재생, 재시작 후 알람 복원, 걸음 감지, 그리고 아래에 설명한 Google Play 및 RevenueCat 라이브러리가 쓰는 네트워크 접근에 필요한 권한을 요청하거나 사용할 수 있습니다. 내부 테스트 빌드는 Google Play 결제 권한도 사용합니다.

신체 활동 권한은 걷기 미션을 사용할 때, 또는 내부 테스트 빌드와 비공개 베타 빌드에 포함된 걷기 센서 테스트를 사용자가 실행할 때에만 요청합니다. 기기 센서의 걸음 수는 그 미션이나 테스트가 진행되는 동안에만 사용되며 저장되거나 전송되지 않습니다. 동작 권한이나 호환 센서를 사용할 수 없으면, 사용자가 울리는 알람에서 벗어나지 못하는 일이 없도록 RisePilot이 명확히 표시된 수동 대체 방법을 보여 줍니다.

데이터 내보내기, 가져오기, 삭제

사용자는 「데이터 및 개인정보」 화면에서 기기에 저장된 알람 설정, 알람, 프리셋, 플래너 항목, 화면 설정, 최신 선택형 건강 요약을 JSON 파일로 저장할 수 있습니다. 저장 위치는 Android의 시스템 파일 선택기로 사용자가 고르며, RisePilot은 내보낸 파일을 업로드하지 않습니다. 이 파일에는 개인정보가 들어 있을 수 있으며, 저장된 뒤에는 사용자가 고른 앱이나 저장 위치가 파일을 다룹니다. 벨소리 오디오 파일은 포함되지 않습니다. 사용자는 직접 고른 내보내기 파일을 가져올 수도 있습니다. RisePilot은 이 파일을 기기 안에서 읽으며, 가져오면 현재 기기의 데이터가 대체됩니다.

사용자는 앱에서 이 로컬 사용자 데이터를 삭제할 수도 있습니다. RisePilot은 삭제 전에 예약된 알람을 먼저 취소합니다. 이 삭제는 Google Play 구매 기록, Health Connect에 저장된 원본 기록, Android가 관리하는 권한, 사용자가 다른 곳에 저장한 내보내기 파일은 지우지 않습니다. 구매 기록, Health Connect 기록, 권한은 각각 Google Play나 Android 설정에서 관리할 수 있습니다. 내부 테스트 빌드에서는 아래에 설명한 RevenueCat 데이터도 지우지 않습니다.

데이터 보관

RisePilot은 사용자가 앱에서 삭제하거나, 데이터 파일을 가져와 대체하거나, RisePilot을 제거할 때까지 로컬 데이터를 기기에 보관합니다. 앱을 제거하면 Android가 앱의 로컬 데이터를 지웁니다. 건강 요약은 새로고침할 때마다 대체되며 「모든 사용자 데이터 삭제」로 지워집니다. Google Play와 Health Connect는 각자의 설정과 정책에 따라 자체 기록을 보관합니다. Google은 Google Play 인앱 업데이트 확인에 쓰인 데이터가 정해진 보관 기간이 지나면 삭제된다고 밝힙니다. 내부 테스트 빌드에서 RisePilot의 데이터 삭제는 RevenueCat의 기록이나 Block Store 사본을 지우지 않습니다. 내부 테스트 버전 0.9.10 (22)에서는 저장된 구매 상태도 지우지 않으며, 이 상태는 앱을 제거할 때까지 남습니다. 내부 테스터는 이메일로 RevenueCat 기록 삭제를 요청할 수 있습니다.

내부 테스트 빌드의 구매

내부 테스트 빌드에는 인앱 구매 테스트가 포함되어 있습니다. 구매는 Google Play가 처리하며, RisePilot은 카드나 기타 결제 정보를 받지 않습니다. 이 빌드는 구매 상태를 확인하기 위해 구독 관리 서비스인 RevenueCat을 사용합니다. 앱이 실행되는 동안, 즉 앱이 시작될 때(알람을 울리거나 휴대폰을 다시 시작한 뒤처럼 백그라운드에서 시작될 때 포함), 앱이 다시 화면에 나타날 때, 그리고 테스터가 구매 화면을 열거나 구매 또는 복원할 때 RevenueCat 라이브러리는 RevenueCat에 다음을 보낼 수 있습니다.

  • 라이브러리가 만든 무작위 앱 사용자 ID
  • 구매 토큰, 상품 ID, 가격, 통화 같은 Google Play 구매 정보
  • 기기 모델과 제조사, Android 버전, 언어 설정, 스토어 국가, 앱 패키지 이름과 버전, 라이브러리 버전 같은 기기 및 앱 정보

Google Play도 갱신, 취소, 환불 같은 구매 관련 변경 사항을 RevenueCat에 보냅니다. RevenueCat은 이 정보를 구매 확인과 구매 통계 제공에 사용합니다. 이 빌드는 RevenueCat의 SDK 진단 기능도 켜며, 이 기능은 응답 시간, 오류 코드, 상품 ID, Google Play 앱 버전 같은 라이브러리 동작에 관한 기술 정보를 RevenueCat에 보냅니다. 이 빌드의 Google Play 결제 라이브러리는 구매 과정 로그를 Google에 보낼 수도 있습니다.

테스터가 구매를 하면 RevenueCat 라이브러리는 무작위 앱 사용자 ID를 기기의 Google Block Store에 저장할 수 있습니다. Google 백업이 켜져 있으면 Block Store는 이 ID를 테스터의 Google 계정에 백업하고, 앱을 제거한 뒤에도 보관할 수 있습니다. 구매를 복원할 때 라이브러리는 이 ID로 새 설치를 이전 구매와 연결할 수 있습니다.

RisePilot도 확인된 구매 상태, 즉 Plus 이용 여부, 확인 시각, 종료 시각, 평생 이용 여부, 테스트 구매 여부를 기기에 저장합니다. 앱을 제거하면 이 상태와 RevenueCat의 로컬 파일이 지워집니다. 현재 버전은 사용자가 모든 사용자 데이터를 삭제할 때 이 상태도 지우지만, 내부 테스트 버전 0.9.10 (22)은 지우지 않습니다. RisePilot에서 데이터를 삭제해도 RevenueCat의 기록이나 Block Store 사본은 지워지지 않습니다. 내부 테스터는 이메일로 RevenueCat 기록 삭제를 요청할 수 있습니다(연락처 참고).

비공개 베타 빌드는 구매나 RevenueCat을 켜지 않으며 이 정보를 보내지 않습니다.

Google Play 업데이트

RisePilot은 새 버전이 있는지 확인하기 위해 Google Play의 인앱 업데이트 라이브러리를 사용합니다. 이 확인에서 Google Play는 기기 정보, 앱 버전, 설치된 앱 모듈과 애셋 팩 정보를 사용하며, Google은 이 데이터가 암호화되고 제3자에게 전달되지 않는다고 밝힙니다. RisePilot은 자체 업데이트 알림 설정만 기기에 저장합니다.

보안

이 방침에 설명한 Google Play 및 RevenueCat 라이브러리를 제외하면 RisePilot은 사용자 데이터를 네트워크로 보내지 않습니다. RisePilot은 다른 앱이 읽을 수 없는 앱 전용 저장소에 데이터를 보관합니다. Android 파일 기반 암호화를 사용하는 기기에서는 처음 잠금 해제하기 전에 필요한 알람 데이터를 기기 암호화 저장소에 보관하며, Android는 이 저장소를 사용자가 휴대폰을 잠금 해제하기 전에도 쓸 수 있게 합니다. 그 밖의 데이터는 휴대폰을 잠금 해제한 뒤에만 쓸 수 있는 자격 증명 암호화(credential-encrypted) 저장소에 보관합니다. 데이터 내보내기 파일은 암호화되지 않은 일반 JSON이므로 믿을 수 있는 곳에 보관해야 합니다. Google은 인앱 업데이트 데이터가 암호화된다고 밝히며, RevenueCat은 전송 중인 데이터를 암호화한다고 밝힙니다.

계정, 분석, 광고

RisePilot에는 사용자 계정이 없습니다. 광고를 표시하지 않으며 광고나 오류 보고 SDK를 포함하지 않습니다. 위에서 설명한 내부 테스트 빌드의 RevenueCat을 제외하면 분석 SDK도 포함하지 않습니다. RisePilot은 Android 광고 ID를 사용하지 않으며 다른 앱이나 웹사이트에 걸쳐 사용자를 추적하지 않습니다. RisePilot은 성인을 대상으로 하며 아동용으로 설계되지 않았습니다.
